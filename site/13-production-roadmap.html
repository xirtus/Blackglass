Production Roadmap

Build the smallest version that proves the inference → handoff → Hydra → intervention loop before spending effort on spectacle. Every phase must end in a playable, testable artifact.

VERTICAL SLICE FIRSTNO ART-FIRST DETOURSAUTOMATED TEST GATES

Phase 0 — repository and contracts

  1. Create Vite/TypeScript/React project, strict type checking, lint/test scripts and deterministic RNG utilities.
  2. Establish simulation/render separation, command bus and versioned save schema.
  3. Add THIRD_PARTY.md, asset registry and license gate.
  4. Set up Playwright smoke tests and screenshot capture.

Phase 1 — ugly but complete game loop

  1. Flat dark map with orthographic/geo camera and pan/zoom.
  2. One carrier moving along a path.
  3. One social contact and one handoff event that creates a child copy.
  4. Dossier, event log, copy tree and one Watch Index circle.
  5. One low-impact intervention and one high-impact abstract intervention.
  6. Pause/speed control, containment metric and mission end.
Exit gate: the game is already interesting with circles, lines and text. If not, do not add photorealistic buildings.

Phase 1B — prove the opposite side before art

  • Add title-screen perspective selection: BLACKGLASS or HYDRA.
  • Use the same Phase 1 scenario seed for both sides.
  • Create a bounded BLACKGLASS AI that reasons only from observations and finite resources.
  • Give HYDRA the active-holder/trust/archive/credibility workspace and high-level disclosure actions.
  • Support control transfer to a descendant holder when the original carrier becomes unavailable.
  • Implement at least three disclosure outcomes and an omniscient post-mission replay.
Dual-perspective exit gate: the same ugly dots-and-lines mission must be strategically interesting from both sides before Phase 2 geographic/presentation expansion.

Phase 2 — D.C.-style vertical slice

  1. Integrate MapLibre and permitted OSM-derived geography around one public leak-point archetype.
  2. Add 500–1,000 explicit synthetic local lives plus background aggregates.
  3. Implement routines, vehicles, 4–6 surveillance source types and observation confidence.
  4. Add social-circle expansion, anomaly scoring, false positives and model disagreement.
  5. Implement archive forms (full copy, excerpt, index) and complete genealogy.
  6. Add 8–12 interventions across administrative, network, mobility and field categories.

Phase 3 — presentation and asset system

  1. Import curated vehicle/human/street/interior library assets with registry checks.
  2. Add LOD population rendering and instancing.
  3. Add procedural vegetation and material families; optional water/weather modules.
  4. Build the final HUD layout, command palette, graphs, tooltips and keyboard workflow.
  5. Add audio: alert language, UI clicks, radio-like chatter abstractions and dynamic tension layers.

Phase 4 — national scale

  1. Add city/state strategic map and cross-city travel.
  2. Represent server/data-center nodes and digital transfers.
  3. Introduce aggregate population model and mirror clusters.
  4. Add media reach, public suspicion, credibility and active-search demand.
  5. Implement persistent campaign authority/trust/technology state.

Phase 5 — global Hydra

  1. Planet/network view and country/city/server aggregation.
  2. Copy-estimation confidence and practical-containment threshold.
  3. Fictional black-program tech tree and spectacular procedural effects.
  4. Systemic infrastructure damage, political costs and endgame scoring.

Phase 6 — campaign content and polish

  1. Author six-act mission ladder and scenario variants.
  2. Add hero actors and limited mission-specific interiors.
  3. Balance model accuracy, false positives, intervention costs and Hydra growth.
  4. Accessibility, tutorialization, localization-ready strings, settings and save migration.
  5. Performance profiling on representative hardware and deployment hardening.
