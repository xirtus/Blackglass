Performance, QA & Save

A deterministic simulation and aggressive level-of-detail system are prerequisites, because the core fantasy depends on scaling from dozens of explicit actors to millions of estimated ones without losing responsiveness.

Performance strategy

SystemRule
Render loopPresentation can run every frame; simulation ticks at a controlled fixed step.
AgentsHero/local explicit; regional event-driven; global aggregate.
Map markersInstanced/deck.gl buffers, not one React component per background person.
CharactersHard cap on simultaneously skinned characters; replace by low-poly or sprite LOD.
PathfindingPrebuilt navigation graphs, cached routes, async workers.
Social graphOnly render neighborhood around selected/pinned nodes; cluster the rest.
HydraExplicit high-value copies + aggregate low-value descendants.
Procedural worldGenerate/cook chunks asynchronously and cache by seed/data hash.
EffectsQuality tiers; expensive weather/water/volumetrics optional to the simulation truth.

Testing pyramid

Unit

Deterministic RNG, trust math, copy genealogy, confidence decay, resource costs, save migration.

Simulation property tests

No orphan copies; parent timestamps precede descendants; budgets never underflow; route endpoints valid; deterministic replay.

Browser / visual

Playwright input tests, critical HUD flows, map selection, screenshot regression, WebGL/WebGPU capability checks.

Scenario validation

  • Every hero actor can reach required scripted anchors.
  • Starting copy genealogy is valid.
  • At least one plausible containment path exists in tutorial/normal scenarios.
  • Difficulty modifiers do not create impossible prerequisite loops.
  • Interventions cannot target invalid entity categories.
  • Every event shown to the player has a provenance and can be inspected.

Perspective-isolation tests

  • HYDRA UI must never expose unobserved BLACKGLASS sensor state, Watch Index scores or queued hidden interventions.
  • BLACKGLASS AI must never read the authoritative copy holder unless an observation supports it.
  • Both perspectives must reproduce from the same scenario seed and command log.
  • Post-mission omniscient replay must reconcile each side’s belief state with ground truth.
  • Difficulty changes budgets, calibration and latency — not privileged hidden-state access.

  scenarioSeed,

}

Debug instrumentation

Ship internal development overlays for FPS, draw calls, GPU frame time where available, active explicit agents, aggregate population size, worker tick cost, event queue length, copy count by LOD, rendered graph nodes and memory estimates. The simulation should have a reproducible “dump state” function for bug reports.

Graceful degradation

Gameplay truth must survive reduced graphics. If WebGPU-only water or volumetric weather is unavailable, replace it with cheaper presentation while keeping weather/intervention state intact. The intelligence dashboard and simulation are the product; visual spectacle is enhancement.
